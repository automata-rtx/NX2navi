Make the complete path to useful GPU submission cheaper and more predictable. Establish resource knowledge once at the appropriate boundary and carry it through preparation, binding, queued use and reclamation. Do not add a new cache that leaves the same discovery and ownership work underneath. Include introduced checks, copies, synchronization, metadata and retained memory in the result.

| Content and visibility | Range/subresource authority | Which producer supplies which contents at an ordered observation point; CPU, GPU or mixed/unknown authority, with dependencies. Aliases refer to the same authority domain instead of declaring independent ownership. |
| Prepared representation | Preparation provider | Exact content identity plus format, dimensions, mip/layer layout, interpretation and producer/conversion-policy identity. Records whether and how these contents can be reproduced. |
| Physical residency | Backend allocation owner | A particular allocation/view instance, capacity charge and pending producer operations. Logical identity can survive its absence. |
| Captured use | Recording/submission owner | The exact instance/view, access, dependencies and lifetime required by recorded work. Neither guest release nor cache eviction can revoke it. |

Handles have incarnation protection; recycled slots cannot validate old consumers. Use stable publication/acquisition with lifetime protection, not raw pointers into movable tables. Metadata and subscriptions have a budget and retirement policy too. Absence, unknown identity, failed preparation and temporarily unavailable capacity are distinct outcomes.

**Reconstructibility is explicit:** a verified immutable payload, a valid reread of the same source version, a retained GPU-only version, or no available reconstruction route. A digest names bytes but does not reproduce them. A recipe is not a payload. Retire a last physical copy only when no consumer needs its contents or an admitted reconstruction route preserves them. Retaining identity cannot justify keeping arbitrary data forever; bounded pressure policy may drop unneeded identity as well.

Separate **ResolveCurrent(source, observation)** from **AcquireExact(version)**. A live writable guest source is conditional input for the former, not a promise to reproduce the latter. Without an exact-version obligation, eviction may preserve identity and reobserve current contents on demand. Finalized/queued/history-required old versions need an immutable recovery source or retain their physical copy. This avoids both unsafe rereads and retaining every captured payload forever.

**Initial visibility policy:** use the existing ordered ordinary-source freshness boundary, after the required guest event/deferred-handle resolution. Name the exact owned captured bytes and retain the pre-copy invalidation cutoff; do not claim those bytes all existed at that cutoff. `memory.c:mem_read_hold` prevents unmapping, not CPU stores, and the epoch-based observation is not an atomic snapshot guarantee. Consumers in the same semantic observation scope can share its result; later scopes revalidate source evidence. Cross-address reuse requires separately verified equality or trusted provenance. Stronger producer-completion certificates require verified integration, not merely a CLEAN page result. This preserves a defined compatibility observation path without making the core depend on atomic guest snapshots or speculative whole-game write instrumentation. Race handling cannot become an unbounded retry/copy loop.

Observation scopes follow `make_fresh_source`/`make_fresh_snap` and the late-event resume behavior in `vk_exec_xfer.c:ev_met` and `vk_backend.c:submit_sync`, not a blanket frame or original-submit scope. A late CPU signal/resume requiring fresh copies opens new observations. Registration/finalization (`nvn_api_obj.c`), mapping replacement (`memory.c`) and explicit `nvn_guest_written`/pool-flush notifications invalidate affected associations. Do not advance a capture watermark past writes absent from its payload. Compatibility preserves existing visibility behavior; it does not certify legacy mixed-authority writeback as correct fine-grained ownership.

Authority is tracked in backing-relative byte intervals and image subresource/region coverage supplied by adapters. Unknown layout/coverage conservatively covers the affected domain; page dirtiness is invalidation evidence, not exact write coverage. GPU partial writes preserve untouched authority and producer dependencies. Shared immutable versions detach before writes when old readers still need them; ordered exclusive updates may reuse storage. No requirement to copy every GPU write. A recorded write creates a pending producer version: submit attaches real completion, cancellation removes that producer and invalidates/replans its unsent dependents. Submitted consumers cannot depend on a cancelable unsent producer.

## Operations, publication and scheduling

1. **Identify/observe:** translate a registration into source/view identity at the operation's semantic observation point. Preserve the required registration incarnation/history across finalization and reuse; delayed resolution cannot simply consult the newest host registration. An immutable command plan contains requirements and offsets, not permanently resolved resources. Event waits, indirect handles and paused streams can delay the observation point; adapter hooks define which registration scope they retain.
2. **Request preparation:** request a representation for a content version and usage. Deduplicate identical work; return an available record, dependency ticket, unavailable source or explicit failure. A query does not secretly allocate, revive or upload.
3. **Admit and prepare:** reserve peak additional capacity, execute independent decode/convert/upload work, then publish only against the still-matching request/incarnation. Obsolete completion cannot overwrite a newer association. Other consumers may still retain the completed older version. Cancellation releases or transfers reservations exactly once.
4. **Capture use:** atomically acquire a lifetime-protected residency/view record and its producer dependencies. CPU metadata readiness does not imply GPU upload completion. If invalidated before acquisition, resolve again; after acquisition, later replacement cannot mutate the captured record.
5. **Record, submit or cancel:** deduplicate instance holds per recording scope rather than allocating per draw. Transfer holds to the actual completion conditions on submission; release canceled CPU work without losing already submitted work. Split submissions, paused continuations and multiple queues retain their own obligations. A maximum timeline value is sufficient only within one proven ordering domain.
6. **Release/reclaim/reacquire:** remove current demand separately from captured uses. Select eligible physical owners, preserve useful source/prepared knowledge and account pending retirement separately from available capacity. Reacquire from a valid retained version/provider without rebuilding the entire discovery chain.

Publish changes to relevant dependents; do not fan out eagerly through every dormant alias on a mutation. Bounded notifications can coalesce. Lost history makes affected evidence unknown and requires reconciliation before use; it never proves unchanged data. Unrelated changes should not invalidate migrated binding groups. A ready unchanged binding uses existing records and batch-held captures, without allocating a task, ticket or graph node per draw. Jobs are created for actual missing/change work. Active working-set maintenance must not grow with every area ever visited.

Serialize mutations within ownership domains; publish immutable records for recording workers. Acquire and pin the incarnation under its publication lock before releasing that lock. Where multiple domains change together, acquire index/topology protection first and domain locks in stable ID order. Admission synchronization is separate: no ownership lock while reserving/waiting. Provider work, driver allocation/destruction and callbacks run outside these locks. A compatibility handoff marks the domain transitioning, pins its old contents, performs external work unlocked, then commits only if its transition identity still matches. Concurrent requests receive that transition dependency; legacy callbacks cannot reenter the core while holding legacy locks. Parallelism comes from independent ready work, not reordering required guest effects.

Required work inherits priority through its unresolved prerequisites; another required dependency cannot starve indefinitely. Speculation yields CPU, memory and queue capacity to demand. Use runnable continuations, not workers waiting on tasks queued to the same exhausted pool; submission/completion remain runnable. A late discovery uses the same preparation path without a hidden resolver. Waits release ownership locks. For the first texture path, admission covers incremental peak from source capture through upload submission: input, conversion output, destination and staging. Later segmented producers must retain a guaranteed drain reservation or bounded spill/discard route, never all capacity while awaiting an unreserved successor. Reordering respects guest events, queries, writes and required ordering.

## Memory and prepared inputs

Use one accounting/policy contract across producers, with specialized allocators and scheduling domains. Track system commit headroom, physical RAM pressure, device budget, compatible reusable allocation capacity, reservations and pending destruction separately. A scheduled free is not available memory; generic allocator slack is not guaranteed suitable for the requested format/type. Initial migration must account legacy allocations and route competing growth through admission adapters before claiming coordinated pressure handling.

General draw scratch needs a resolved access manifest before resource declaration, using the [preparation and recording contract](#operations-publication-and-scheduling). Raw bindings, prepared bindings and effect capture share the selected spans, alignment and retained inputs from that manifest. Worker grants must be ready before group publication. Cached descriptors and deferred motion keep the spans they name through their actual use, so prefix completion can retire only spans free of those later uses.

Admission covers demanded/speculative pipelines, textures, mirrors, snapshots, staging and copy-on-write peaks. An all-or-none ticket reserves RAM/commit allowance, eligible GPU heap/type and staging capacity under short accounting synchronization; refusal reserves nothing. One owner transfers/settles it exactly once. Existing allocations remain charged once; reservations cover incremental peak, including simultaneous old/new contents. Staging capacity is not an extra duplicate physical-memory charge, and ready lookups do not reserve resident allocations again. Estimate opaque driver/SDK growth conservatively and reconcile observations. More memory may retain useful data without proportional scans; fixed mirror shares and texture thresholds remain policy, not invariants.

Track pressure by constrained pool, producer, proposed victims and actual relief. Pending retirement suppresses duplicate victim selection in its capacity domain, never grants free capacity. Destruction settles allocation charges once; driver-retained blocks and system commitment reconcile separately. Bound unsuccessful scans and resample after relevant completions. Stop optional growth responsible for persistent pressure rather than repeatedly evicting textures for unrelated compiler allocations. Stale telemetry permits bounded conservative progress, not unlimited speculation.

If the essential working set cannot fit, use an explicitly supported placement/reconstruction path or report failure; do not loop evicting and rebuilding it or silently discard required effects. Distinguish recoverable pressure, unavailable source and device/allocation failure. Shutdown, cancellation and settings changes drain or retire the relevant generation, not leak obsolete reservations.

Preparation providers accept runtime source observations, owned captured payloads or future installer records through the same version/representation contract. Installer records need source provenance, payload location/integrity, format/mips/layers and converter/policy compatibility. They cover eligible static ASTC only, preserving glyph replacement identity and original visual interpretation. Old records become misses when incompatible. Disk payloads, staging and resident images have distinct lifetimes; a persistent digest does not require keeping decoded data in RAM. Implement the producer later without introducing another independent cache/ownership system.

Temporal/MV/DLSS/FG resources declare frame/history generation and actual graphics/presentation/SDK completion obligations. Resize or Apply creates a compatible new configuration generation and retires old users safely; it does not reinterpret old history. Upscaling and frame generation use actual game/render motion data. Seamless resolution changes resize all affected framebuffers together. Anisotropic filtering is supported. Preserve the game-authored visuals and ordinary resource, lighting and depth behavior. Project-specific AO, extended draw distance and shadow enhancements, including shadow-resolution overrides, are outside the support and acceptance scope. Reserved enhancement hooks include contact shadows, `SHADOW_SCALE`, `SHADOW_RES`, `SHADOW_RANGE` and enhancement-specific foliage shadow culling or VRS. Game-authored shadows still use the ordinary framebuffer, depth and sampling contracts. The contracts permit later bounded frame overlap without enabling one-frame-ahead now.

## Implementation order and confidence checks

**A — Contract seam:** implement source/registration incarnations, authority bridge, representation providers, capture/completion and ledger/ticket interfaces with independent behavioral fixtures and synthetic competing producers. Trace actual registration, finalization, mapping/write, draw, transfer, presentation and cancellation hooks. Use fixed preparation states and existing executors initially, not a generic graph framework. Validate the observation/registration boundaries and lease acquisition interleavings before enabling independent eviction.

**B — Complete first lifecycle:** switch ordinary textures and direct/bindless consumers; finish nonfinal eviction/reacquisition and canceled/paused work, removing migrated discovery/invalidation/revival code. Before accepting coordinated memory behavior, adapt every competing growth path active in the supported configuration: pipeline demand/background/startup/warm/preparation builds (`gate_enter`, `seed_pipelines`, `lb_warm_worker`), texture/COW/source payloads, mirrors, staging arenas (`vk_staging`, `vk_staging_at`), snapshots and attributed driver/SDK growth. Existing fixed allocations enter as baseline charges. These adapters replace independent admission policies, not buffer/pipeline content ownership. Keep checkpoints and recoverable path selection, not two active owners.

**C — Complete the remaining foundation:** migrate writable/aliased images, buffers and active temporal/presentation users through the same ownership, observation, admission and lifetime contracts; complete canonical backing/registration identities and preparation progress. Replace competing old decisions as consumers migrate. Use correctness and pressure/area-return checks, not performance gates, between boundaries. Installer production and broader configuration/features remain separately approved work.

**D — Integrated optimization:** after the agreed foundation is complete and correct, evaluate whole-path performance and pursue coordinated optimizations. Existing evidence informs the architecture but does not justify leaving a required consumer on the old manager.

Before enabling each boundary, exercise these obligations:

| Scenario | Required result |
| --- | --- |
| Same address/descriptor reused while old command waits | New incarnation resolves new data; old consumer retains its intended old version. |
| CPU write or remap during preparation | No false clean publication or obsolete association overwrite; ordering/fallback is explicit. |
| GPU writes one part of an overlapping resource | Preserve untouched data and dependencies; no CPU-page-only ownership takeover. |
| Buffer/physical-address writer overlaps a sampled texture | A private pre-emission image can capture the same operation's read phase when prior producers permit it. The later guard still excludes subsequent observations, including mapped aliases. Earlier pending work, unordered reads and native feedback keep independent authority checks. |
| Evict/reacquire with a pending upload, recording worker or finalized descriptor | Reclaim only after obligations discharge; reproduce the exact required version or retain it. |
| Two consumers request the same missing version; one cancels | One preparation job where compatible; surviving demand retains priority, budget and results. |
| Bindless stale entries, event overflow, restarted worker | No dangling view; reconcile affected dependencies before use without scanning all historical assets every frame. |
| Memory shrinks with unsent work and pending frees | Progress without circular reservation waits, double credit or eviction/reload loops. |
| Concurrent admission, saturated stages, promoted speculative job | Atomic tickets; guaranteed drain; required prerequisites make progress without worker-pool deadlock. |
| Unchanged ready bindings; compiler/startup pressure | No per-draw job/reservation allocation; preparation modes remain accounted; unrelated pressure does not repeatedly discard textures. |
| Pause/resume, split/canceled submission, FG/presentation, Apply | Each actual user has a completion obligation; cancellation cannot release submitted users. |

Use host interleaving and state tests for contracts, then the native Vulkan probes and in-game correctness routes for integration. Prioritize old pins across same-address reuse, exact partial readback, opaque producer order, held replay cancellation, bindless replacement and pressure recovery. Use a verified candidate with recorded save, settings and route to assess world progress and inspect matched Kokiri and Field captures for geometry, materials and presentation. Record which active render or replay modes the probes and route actually exercised. A diagnosed boot or unsupported source cannot establish visual acceptance. During foundation work, verify intended contents, ownership, lifecycle completion, bounded progress and removal of displaced responsibilities. After integration, measure the whole preparation-to-submission chain and fresh/area-return FPS and lows, including retained adapter costs.
