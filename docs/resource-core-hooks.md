The obligations below remain acceptance requirements, not a claim every hook has migrated. Recheck function names and semantics after implementation changes.

Recorded writes are pending producers until submission binds real completion obligations. Canceling unsent work removes its pending producers and reconciles dependent unsent work; already submitted split parts remain valid. Callback delivery and GPU execution completion can differ, so both obligations must be named where applicable.

`vk_texture.c:source_registration_release` releases a source lease when its `Tex` changes guest identity or is destroyed. Shared source records survive another owner's release. The registry collector visits retired records only. Descriptor-history retirement is host-tested infrastructure; live descriptor resolution still uses the legacy slot owner, without a duplicate registry index. Shader physical-write classification runs on loaded SPIR-V, including existing caches; mesh-output count instructions do not create guest-memory write obligations.

## Consumers and exact-use ownership

The NVN command adapter records draw and dispatch operations for Vulkan replay. Separately, `nx2navi_xlate` lowers SM86 shader binaries to Maxwell instruction bytes in memory for the vendored Ryujinx shader translator. `Program.cs` requests Vulkan SPIR-V and writes resource reflection including type, handle, array length, separate image/sampler and pool kind. The runtime parses the reflection and remaps the descriptor bindings. The texture and pool code then resolves the registration at the ordered read, selects its concrete view and checks its compatibility with the shader's required kind. [NVN adapter](../runtime/nvn_api_cmd.c), [SM86 lowering](../tools/xlate/AmpereLowering.cs), [translator front end](../tools/xlate/Program.cs), [reflection parser](../runtime/gfx_shader.c), [descriptor remapping](../runtime/vk_pipeline.c), [texture selection](../runtime/vk_texture.c), [pool and native views](../runtime/vk_exec_draw.c).

A later whole-pool refusal for a registered RGBA8 view occurred during renderer preparation. The refusal alone does not identify the index an invocation would read.

The upstream 0.9.1 source at `ef3466ce4f8f27b750171d32b5275ba291c43e55` copied the registered view into the texture slot and passed it to the resolver (`git show ef3466c:runtime/vk_texture.c`, lines 4083 and 4142). The depth-twin substitution excluded separate samplers (`git show ef3466c:runtime/vk_exec_draw.c`, lines 849, 2470-2479, 2780-2785 and 2957-2969). These are source observations. `resource_core_vma.c:create_admitted` first tries compatible existing allocator blocks without charging new heap or commit growth. It still admits the host-memory working span against physical RAM headroom; block reuse does not prove its pages are resident. `resource_core_budget.c:limit_at` adds tracked retained/pending bytes back to the sampled allowance before subtracting ledger charges, avoiding duplicate accounting. A required staging refusal can therefore be a RAM-floor refusal even with commit capacity remaining. Its domain mask and sampled/reserved/pending/unobserved values distinguish that case from leaked charges. Giving back buffers does not grant capacity until a new sample demonstrates relief; the current bounded retry can still terminate required work and is not a resumable progress policy.

## Evidence boundary

`vk_texture_content.h:content_write_begin` holds the exact source instance across destination allocation/reclamation and records preservation from that image, even if its current residency was detached. The hold transfers to backend upload/scene deferral after recording. Failed preservation stops writable exposure and uploads; synchronous WriteTexels still has an explicit terminal failure rather than a resumable continuation. `content_recovery_wait_source` keeps failed captures eligible for bounded retry on source-specific authority/mapping/protection changes, without treating advancing clean cutoffs or unrelated writes as new work.

Host fixtures exercise the primitives and connected service/caller cases they actually execute. The registry retains bounded registration history, but runtime continuation scopes do not yet resolve through that history. Descriptor publications hold exact instances and completed dormant holds can retire under pressure; required capacity backpressure and guest registration horizons still need migration. Synthetic tests cannot establish live GPU ordering or supply missing adapter semantics.

They cannot prove actual hook coverage, source visibility at game events, Vulkan image/layout/barrier correctness, bindless reachability, SDK retirement, telemetry accuracy, or reduced frame cost. Foundation completion must connect and correctness-test these hooks, including mixed domains and all active growth paths. Remove old responsibilities as their consumers move to the new authority; a compatibility adapter must not remain a second manager. Complete the agreed replacement before performance optimization. Whole-chain timing and performance evaluation follow integration, rather than deciding whether individual foundation components should be completed.
